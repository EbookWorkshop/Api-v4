## 阶段 3：发送端改造

### T3.1 `CollectExecutor` 在任务入口创建 emitter
- **文件**：`2-application/services/executor/CollectExecutor.js`
- **内容**：
  - `execute()` 内根据 `payload` 构造 `emitter = new CollectEventEmitter(this.#eventManager, { taskId?, batchId, ctx: { bookId, ... } })`
  - 将 `emitter` 注入到 `services`，传递给各 Collector
- **依赖**：T0.4、T2.1
- **备注**：`taskId` 目前 Runner 层没透传到 payload，如果 emitter 需要它，需在 T2 一并往 param 里塞 `taskId`；否则 `taskId` 可留空

### T3.2 `ChapterCollector` 改用 emitter
- **文件**：`2-application/services/collectors/ChapterCollector.js`
- **替换点**：
  - `emitToMain(UPDATE_CHAPTER_START, { chapterId, bookId })`
  - `#resultHandle` 内 `emitToMain(UPDATE_CHAPTER, {...})`
- **改法**：
  - 构造函数接收 `emitter`
  - `emitter.start(UPDATE_CHAPTER_START, { ctx: { chapterId } })`
  - 成功：`emitter.success(UPDATE_CHAPTER, { ctx: { chapterId }, message })`
  - 失败：`emitter.failure(UPDATE_CHAPTER, { ctx: { chapterId }, error, message })`
  - `#resultHandle` 返回值保持后端调用者兼容（可返回 `{ ok, message, ...payload }`）
- **依赖**：T3.1

### T3.3 `FileCollector` 改用 emitter
- **文件**：`2-application/services/collectors/FileCollector.js`
- **替换点**：`#resultHandle` 内 `emitToMain(FETCH_CHAPTER, { url, result, message })`
- **改法**：成功带 `data: { filePath, fileName }`；失败带 `error`
- **依赖**：T3.1

### T3.4 `WebBookCollector` 改用 emitter
- **文件**：`2-application/services/collectors/WebBookCollector.js`
- **替换点**：`#resultHandle` 内 `emitToMain(eventType, { result, message })`
- **改法**：
  - `CREATE_BOOK` 成功：`data: { bookId, bookName }`
  - `UPDATE_INDEX` 成功：`data: { addedCount }`
  - 失败：`error`
- **依赖**：T3.1、T1.1

### T3.5 `CollectExecutor` catch 块改用 emitter
- **文件**：`2-application/services/executor/CollectExecutor.js`
- **替换点**：`execute()` catch 内 `emitToMain(msgEvent, {...})`
- **改法**：用 `emitter.failure(msgEvent, { error: _error, message })`
- **依赖**：T3.1 ~ T3.4

## 提交批次建议

如果要拆成多次 PR：

| PR | 内容 | 可独立合并 |
|---|---|---|
| PR-1 | 阶段 0 全部 | ✅ 无副作用 |
| PR-2 | 阶段 1 全部 | ✅ 修 bug |
| PR-3 | 阶段 2 + T3.1 | ✅ 上下文透传，未改语义 |
| PR-4 | T3.2 ~ T3.5 + T4.1 | ⚠️ 必须一起合，否则发送/接收不匹配 |
| PR-5 | T5.1 ~ T5.4、T5.6 | ✅ 新功能 |
| PR-6 | T5.5、T6.1、T6.2 | ✅ 收尾 |

**关键风险点在 PR-4**：发送端和接收端必须同步上线。如果做不到同步，可以在 T3.x 阶段让 emitter 同时发旧格式（双写），T4.1 完成后再摘掉旧格式。这是唯一需要预留过渡期的地方。
